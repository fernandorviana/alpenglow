# Tabs — implementation plan

> **For agentic workers:** executed inline in the session that wrote the spec (superpowers:executing-plans); steps use checkbox syntax. Kept short on purpose, like `2026-09-12-elevation-and-states.md`: the spec carries the decisions and the numbers, this carries the order.

**Goal:** `Tabs` in the package — underline, segmented and pill over one WAI-ARIA tabs behaviour — with `elevation/sm`, its contrast cases, and the `/tabs` docs page.

**Architecture:** One client component, `src/components/Tabs/Tabs.tsx`, data in through `items`; a roving-tabindex list of `button[role=tab]` and one mounted `tabpanel`. One CSS Module with three variant blocks; the segmented thumb is a single element translated by a `--ap-tabs-index` custom property over equal columns. Keyboard logic is a pure helper so it is tested without the DOM.

**Tech Stack:** React 19, TypeScript, CSS Modules, Vitest 5 + jsdom + Testing Library, axe-core through `src/test/axe.ts`.

**Spec:** `docs/superpowers/specs/2026-09-18-tabs-design.md` — read it first.

## Global Constraints

- **Do not commit.** Fernando asks for the commit and the push separately. When he does: stage by path, never `git add -A`.
- No colour literals; timing from the motion tokens; `box-sizing` declared for every sized box; every `var(--ap-…)` real; `'use client'` on the module; the React Compiler lint (no synchronous `setState` in an effect — derive during render).
- Dark rules are written twice, under `@media (prefers-color-scheme: dark)` with `:root:not([data-theme='light'])` and under `:root[data-theme='dark']`, as Badge does.
- Comments record the decision, not the mechanism.
- Never hand-edit `src/styles/*.css`; run `npm run build:css`.
- The Figma file key stays out of the repository.
- Verify with `npm run check` and `npm run build:docs`.
