# Table Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Table component Alpenglow's tokens already promise — presentational, with sorting and selection as controlled state.

**Architecture:** A single generic React component over a real `<table>`. Columns are configuration (`key`, `header`, `cell`, `align`, `sortable`, `width`, `primary`); cell content is whatever the caller's `cell` returns. Sorting and selection are controlled — the component derives the header checkbox's `indeterminate` state and the `aria-sort` placement, and reports intent through callbacks. Two pure helpers (`nextSort`, `headerSelectionState`) hold the logic that is worth unit-testing without a DOM.

**Tech Stack:** React 19, TypeScript 5.7 (strict), CSS Modules, Vitest 5 + jsdom + @testing-library/react, Next.js 16 App Router for the docs page.

**Spec:** `docs/superpowers/specs/2026-09-09-table-design.md` (commit `29d12e6`)

## Global Constraints

- **No colour literals in component files.** Every value is a token via `var(--ap-*)`. The only literals permitted are geometry that follows from the scale (row and header heights, column widths).
- **Never hand-edit `src/styles/tokens.css` or `src/styles/tailwind-theme.css`.** They are generated by `npm run build:css`; CI regenerates and fails on a diff.
- **The original product's and design file's names must not appear** in code, filenames, packages or technical documentation. The private context file names them; this repository does not.
- **Strict TypeScript.** CSS Module class lookups need the non-null assertion in tests: `styles.foo!`.
- **Test names are sentences that state the decision**, and comments explain *why*, matching `Badge.test.tsx`.
- **Header band is `surface/base`, not `surface/sunken`** — in light, `surface/sunken` (`#EBEEF1`) is the same hex as `border/subtle` and swallows the separator.
- **Selected row uses `interactive/selected`**, not the byte-identical `surface/accent-subtle`.
- **Figma `radius/md` (8) is the code's `radius/lg`.** Radius names are offset by one step above `sm`.
- **Row height is set on the row and content is centred vertically.** Padding is horizontal only. Padding-derived heights give 62px rows that look nearly right.
- **Density values:** `comfortable` = 72px row / 44px header / `spacing/200` horizontal; `compact` = 48px / 36px / `spacing/150`.
- **Container-query collapse threshold: `40rem`** of container inline size.
- **Run `npm run check`** (typecheck then the full suite) before every commit.

/**
 * Table
 *
 * A real <table> in a scrolling region. Every colour is a token; the only
 * literals are the row and header heights and the widths of the two special
 * columns, which are geometry from the drawing rather than values from the
 * scale.
 *
 * The header band is `surface/base`, NOT `surface/sunken` — even though that
 * token's own `use` string advertises "table headers". In light, `sunken`
 * resolves to #EBEEF1 and `border/subtle` resolves to #EBEEF1 as well, so a
 * header painted `sunken` would swallow the separator beneath it. Both clear

- [ ] **Step 4: Write the component**

Create `src/components/Table/Table.tsx`:

```tsx
import type { HTMLAttributes, ReactNode } from 'react';
import styles from './Table.module.css';

export type SortDirection = 'asc' | 'desc';
export type Sort = { key: string; direction: SortDirection };
export type ColumnAlign = 'start' | 'center' | 'end';
export type TableDensity = 'comfortable' | 'compact';

export type Column<Row> = {
  /** Stable identifier, and the value reported as the sort key. */
  key: string;
  header: ReactNode;
  /** Whatever should appear in the cell. */
  cell: (row: Row) => ReactNode;
  /** Defaults to 'start'. Use 'end' for numbers. */
  align?: ColumnAlign;
  sortable?: boolean;
  /** Any CSS width. Applied via <col>, so it does not fight the cells. */
  width?: string;
  /** Survives the collapse to a list. First one in source order wins. */
  primary?: boolean;
};

export type TableProps<Row> = {
  /** Required. Rendered as a visually hidden <caption> unless captionVisible. */
  caption: string;
  captionVisible?: boolean;
  columns: Column<Row>[];
  rows: Row[];
  getRowId: (row: Row) => string;
  /** Shown in place of rows when `rows` is empty. Defaults to "No rows". */
  empty?: ReactNode;
} & Omit<HTMLAttributes<HTMLDivElement>, 'children'>;

/**
 * Sorting and selection arrive in later tasks. What is here is the part that
 * has to be right before anything else matters: a real table, named, with
 * scoped headers and a column group.
 */
export function Table<Row>({
  caption,
  captionVisible = false,
  columns,
  rows,
  getRowId,
  empty = 'No rows',
  className,
  ...rest
}: TableProps<Row>) {
  return (
    <div {...rest} className={[styles.wrap, className].filter(Boolean).join(' ')}>
      <table className={styles.table}>
        <caption className={captionVisible ? undefined : 'ap-sr-only'}>{caption}</caption>

        <colgroup>
          {columns.map((column) => (
            <col key={column.key} style={column.width ? { width: column.width } : undefined} />
          ))}
        </colgroup>

        <thead>
          <tr>
            {columns.map((column) => (
              <th
                key={column.key}
                scope="col"
                className={styles.th}
                data-align={column.align ?? 'start'}
              >
                {column.header}
              </th>
            ))}
          </tr>
        </thead>

        <tbody>
          {rows.length === 0 ? (
            <tr className={styles.tr}>
              <td className={`${styles.td} ${styles.empty}`} colSpan={columns.length}>
                {empty}
              </td>
            </tr>
          ) : (
            rows.map((row) => (
              <tr key={getRowId(row)} className={styles.tr}>
                {columns.map((column) => (
                  <td
                    key={column.key}
                    className={styles.td}
                    data-align={column.align ?? 'start'}
                  >
                    {column.cell(row)}
                  </td>
                ))}
              </tr>
            ))
          )}
        </tbody>
      </table>
    </div>
  );
}
```

In `Table.tsx`, above the component:

```tsx
/**
 * asc → desc → none.
 *
 * The drawing shows a caret but says nothing about the cycle. Three states
 * rather than two, because returning to the natural order is useful and a
 * two-state cycle gives the caller no way back.
 */
export function nextSort(current: Sort | null | undefined, key: string): Sort | null {
  if (!current || current.key !== key) return { key, direction: 'asc' };
  if (current.direction === 'asc') return { key, direction: 'desc' };
  return null;
}

const ARIA_SORT = { asc: 'ascending', desc: 'descending' } as const;
```

export function headerSelectionState(
  selectedCount: number,

  if (rowCount === 0 || selectedCount === 0) return { checked: false, indeterminate: false };

'use client';

import { useState } from 'react';
import { DocPage } from '@ui/DocPage';
import { Ratio } from '@ui/Ratio';
import { Avatar } from '@/components/Avatar';
import { Badge } from '@/components/Badge';
import { Table } from '@/components/Table';
import type { Column, Sort } from '@/components/Table';
import { resolve } from '@/tokens/contrast';

type Client = {
  id: string;
  name: string;
  email: string;
  status: 'active' | 'pending' | 'lapsed';
  visits: number;
  seen: string;
};

const CLIENTS: Client[] = [
  { id: '1', name: 'Lisa Roberts', email: 'lisa.roberts@example.com', status: 'active', visits: 14, seen: '2 days ago' },
  { id: '2', name: 'Gary Martin', email: 'gary.martin@example.com', status: 'pending', visits: 3, seen: 'today' },
  { id: '3', name: 'Sanjay Choudhary', email: 'sanjay.c@example.com', status: 'active', visits: 27, seen: 'last week' },
  { id: '4', name: 'Aoife Byrne', email: 'aoife.byrne@example.com', status: 'lapsed', visits: 1, seen: '4 months ago' },
];

const TONE = { active: 'success', pending: 'warning', lapsed: 'neutral' } as const;

export default function Page() {
  const [sort, setSort] = useState<Sort | null>({ key: 'name', direction: 'asc' });
  const [selected, setSelected] = useState<ReadonlySet<string>>(new Set(['3']));

  // Sorting is the caller's job — the table reports intent and draws the
  // state. This is the whole point of the controlled API.
  const rows = [...CLIENTS].sort((a, b) => {
    if (!sort) return 0;
    const dir = sort.direction === 'asc' ? 1 : -1;
    if (sort.key === 'visits') return (a.visits - b.visits) * dir;
    return String(a[sort.key as keyof Client]).localeCompare(String(b[sort.key as keyof Client])) * dir;
  });

  const columns: Column<Client>[] = [
    {
      key: 'name',
      header: 'Client',
      sortable: true,
      primary: true,
      cell: (c) => (
        <div style={{ display: 'flex', alignItems: 'center', gap: 12 }}>
          <Avatar name={c.name} size="md" />
          <div>
            <div>{c.name}</div>
            <div className="alias">{c.email}</div>
          </div>
        </div>
      ),
    },
    { key: 'status', header: 'Status', cell: (c) => <Badge tone={TONE[c.status]}>{c.status}</Badge> },
    { key: 'visits', header: 'Visits', align: 'end', sortable: true, cell: (c) => c.visits },
    { key: 'seen', header: 'Last seen', cell: (c) => c.seen },
  ];

  return (
    <DocPage
      evidence={
        <>
          <p>header on band</p>
          <p>light <Ratio fg={resolve('text/secondary', 'light')} bg={resolve('surface/base', 'light')} /></p>
          <p>dark <Ratio fg={resolve('text/secondary', 'dark')} bg={resolve('surface/base', 'dark')} /></p>
        </>
      }
    >
      <h1>Table</h1>
      <p className="lead">
        Sorting and selection are controlled. The table draws the state and reports the
        intent; it holds nothing and sorts nothing.
      </p>

      <h2>Try it</h2>
      <div className="specimen">
        <Table
          caption="Clients"
          columns={columns}
          rows={rows}
          getRowId={(c) => c.id}
          sort={sort}
          onSortChange={setSort}
          selected={selected}
          onSelectionChange={setSelected}
          selectionLabel={(c) => `Select ${c.name}`}
          rowAction={(c) => (
            <button type="button" className="rowAction" aria-label={`Actions for ${c.name}`}>
              &#8943;
            </button>
          )}
        />
      </div>
      <p className="alias">
        Sort by Client or Visits — three activations return to the natural order.
      </p>

      <h2>Density</h2>
      <p>
        The drawn row is 72 pixels. <code>compact</code> is an addition: a system sold on
        dense, data-heavy interfaces cannot have the table be the component that proves it
        least.
      </p>
      <div className="specimen">
        <Table
          caption="Clients, compact"
          density="compact"
          columns={columns.slice(1)}
          rows={rows}
          getRowId={(c) => c.id}
        />
      </div>

      <h2>Cell content is not the table's business</h2>
      <p>
        The Figma file draws twelve kinds of cell. Only some of them are structure —
        alignment, the selection column, the trailing action. The rest are things put
        inside a cell, so they are what <code>cell</code> returns: an{' '}
        <code>Avatar</code> beside two lines of text, a <code>Badge</code>, a number
        aligned to the end.
      </p>

      <h2>States</h2>
      <div className="specimen">
        <Table caption="Empty example" columns={columns.slice(1)} rows={[]} empty="No clients yet" />
      </div>
      <div className="specimen">
        <Table caption="Loading example" columns={columns.slice(1)} rows={[]} loading />
      </div>

      <h2>Accessibility</h2>
      <p>
        The caption is required, because a table with no accessible name is the most
        common table defect there is. It is hidden unless you ask for it.
      </p>
      <p>
        <code>aria-sort</code> lands on the sorted column and no other, and the control is
        a button inside the header rather than a handler on it, so a keyboard can reach it.
      </p>
      <p>
        The header checkbox derives its mixed state from the selection, and every row
        checkbox gets a name of its own — ten controls called &ldquo;select row&rdquo; are
        useless in a screen reader.
      </p>
      <p>
        A selected row carries <code>data-selected</code>, not{' '}
        <code>aria-selected</code>: that attribute is only valid under{' '}
        <code>role=&quot;grid&quot;</code>, and on a plain table it is invalid ARIA that
        reads as correct.
      </p>
      <p>
        The table sits in a focusable, labelled region, so a keyboard can scroll it
        sideways. Below 40rem of container width it collapses to a list.
      </p>

      <h2>Props</h2>
      <div className="tableScroll">
        <table className="tokens">
          <thead>
            <tr><th>Prop</th><th>Type</th><th>Default</th></tr>
          </thead>
          <tbody>

              ['caption', 'string', 'required'],

              ['rows', 'Row[]', 'required'],
              ['getRowId', '(row: Row) => string', 'required'],
              ['density', "'comfortable' | 'compact'", "'comfortable'"],
              ['sort', 'Sort | null', '—'],
              ['onSortChange', '(next: Sort | null) => void', '—'],
              ['selected', 'ReadonlySet<string>', '—'],
              ['onSelectionChange', '(next: Set<string>) => void', '—'],
              ['selectionLabel', '(row: Row) => string', 'Select row {n}'],
              ['rowAction', '(row: Row) => ReactNode', '—'],
              ['empty', 'ReactNode', "'No rows'"],
              ['loading', 'boolean', 'false'],
            ].map(([prop, type, def]) => (
              <tr key={prop}>
                <td className="tokenName">{prop}</td>
                <td className="alias">{type}</td>
                <td className="alias">{def}</td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </DocPage>
  );
}

## What shipped, where it differs from this plan

Written after the branch closed, from the shipped code, because a plan left
contradicting the thing it produced is the drift this project criticises
elsewhere. The plan above is left as written — it is the record of the intent,
not of the result. Seven differences:

1. **The scroll region landed in Task 1, not Task 6.** Task 1 is what introduces
   `overflow-x: auto`, so Task 1 is where a keyboard loses the ability to scroll
   the table; its stylesheet comment already claimed `role`, `aria-label` and
   `tabIndex` existed, and `.wrap:focus-visible` already styled a state nothing
   could reach. Task 6's step for those attributes is therefore a no-op, and the
   two "scroll region" tests it lists were already in the file. Task 6's real
   content is `primaryKey`, `data-primary`, the `.thead` class and the container
   query.

2. **The collapse spares the selection cell**, along with the empty and loading
   cells. The plan and the spec both say "primary cell and row action only",
   which reads the drawing correctly and under-specifies the component. Recorded
   as a named deviation in the spec, in `Table.module.css` beside the selector,
   in `MEMORY.md` as invariant 8, and on the docs page; a test asserts all four
   survivors and was proven to fail when the selection clause is removed.

3. **`contrast.test.ts` carries three assertions, not two.** The third records
   the measured row-separator ratio (light 1.16, dark 1.31) rather than a floor,
   because the floor first written for it was dominated by an assertion already
   in the file and so could never have failed first.

4. **The docs page shows three composed cells, not twelve.** The drawing's
   twelve cell types are mostly content rather than structure, which is the
   page's own argument: alignment, the selection column and the trailing action
   are the table's business, and an Avatar beside two lines, a Badge and an
   end-aligned number are examples of what `cell` returns.

5. **`app/docs.css` changed, and is not in the file table above.** The docs
   reading measure moved from `.prose` to its children so a specimen can use the
   whole content column. Without it a specimen was 550px, under the component's
   own `40rem` threshold, and every Table on `/table` rendered collapsed on a
   desktop — invisible in its own documentation. Neither jsdom nor the static
   HTML evaluates a container query, so this was only ever going to be found by
   measuring a real browser.

6. **`captionVisible` gained a stylesheet rule and a specimen.** It shipped
   documented and tested with nothing behind it, so asking for it produced the
   browser's centred default.

7. **The Definition of done's test count is wrong** and was overridden during
   Task 9: the branch ends at 314 tests across 12 files. Every other item in it
   holds.
